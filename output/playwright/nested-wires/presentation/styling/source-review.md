Renderer evidence, including deductions:

- SRP: consumes finished scene records to paint/inspect a scene. The added
  `data-converging` is presentation membership, not a new routing responsibility.
- OCP 6: render categories and the >=3 policy are explicit; adding categories or
  a different threshold requires editing this file. Token paint varies externally.
- LSP 7: no substitutable renderer implementation suite demonstrated.
- ISP: readonly scene/wire data and narrow callbacks; every declared callback
  serves rendering, inspection, camera or readiness.
- DIP: React/React Flow belong in this adapter; Layout imports enter its public
  contract. No Layout builder call, private foreign import or sibling behavior import.
- DRY 9: three wire layers still serialize the same points. Mouth membership is
  centralized in `wireMouths`; paint values live only in Design System tokens.
- KISS 9: camera focus, diagnostic selection and primary selection are separate
  existing concepts in one view. New grouping is a count pass and membership pass.
- YAGNI: no geometry adapter, alternate layout, dependency, general grouping
  framework, extra state or retry added.
- Typed outcomes: injected travel validation remains its typed result; this
  synchronous view adds no fallible I/O. Grouping is total over admitted wire data.
- Retry/failure: renderer entry comment names reload reconstruction; grouping is
  local and selection replaces state. Clearing restores default paint deterministically.
- Depth: public component hides React Flow records, SVG rendering, hit targets,
  focus, selection and diagnostics behind the existing scene/callback interface.
- Demeter: direct immutable scene records and local collections; no service chains.
- Immutability 8: existing midpoint cursor and new invocation-local counts mutate;
  inputs, wire segments, ports and scenes are never modified. `useMemo` depends
  only on the frozen wires, not selection.
- Type safety: no `any`, suppression or unchecked cast; existing `as const`
  narrows a literal. Readonly inputs/output set retain the contract.
- Cognitive style 7: existing conditional JSX/record assembly has multiple idioms;
  the separate Sonar <=2/function gate remains unchanged and passes.
- Testability: finished scene, validation and readiness are injected; no ambient
  I/O/clock in the renderer. The real browser audit independently derives groups
  from M6 JSON and verifies paint/selection without exposing private helpers.

Generated token names: readonly declaration data, no behavior, casts, error paths
or effects. LSP 7 is not demonstrated; depth 5 reflects data-only output. Source
JSON extends the compiler input; `pnpm tokens:check` verifies the generated bytes.

CSS/JSON/generated styles are declarative build resources with no functions to
score for Sonar. All changed visual values use named central tokens. Existing
unrelated literal CSS is unchanged. The compiler regenerates base, semantic,
theme and preference styles; none were hand-edited. Selection group opacities,
label placement/text and hit-target width remain byte-for-byte unchanged.

The standalone MJS/Python audit files follow the inherited terminal-evidence
scope: assertions/I/O errors fail the process, and the caller reruns after a
correction. They are not capability APIs or new `.test.ts` suites. MJS files are
covered by the same ESLint <=2 gate. No test assertion in any inherited runner
was changed. The initial capture chose nonconverging w29 and correctly could not
supply the required converging-selection witness; the final capture uses w22.
No production or acceptance-rule adjustment was made to accommodate that choice.
