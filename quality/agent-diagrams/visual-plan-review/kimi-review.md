# Pressure Test — Novakai Canvas Five-Stage Visual Quality Direction

Single review round, read-only. Verdict up front: **the direction is fundamentally sound and can deliver broad reusable diagram authoring, but Stage 1 as written misdiagnoses the primary gap and contains a sequencing contradiction that will either balloon it or repeat the PR20 mistake of declaring "benchmark" early.** Corrections are cheap and do not require a big-bang replan.

## Verified facts (image and source inspection)

- **story-water-treatment.canvas (19 lines, read in full) declares zero wires.** Nodes are `concept`/`note` cards with small `icon` assets inside grid groups; the only ordering is "1.–5." text prefixes. Both story PNGs confirm: no edges rendered at all. The user's own warning — "paragraphs distributed across attractive boxes" — is literally the current state of the educational family.
- **modules-document-publishing.png is already close to the modules.png reference**: labelled orthogonal wires, ports, function-signature rows in mono font. Residual deltas: container boundary label, external-system color boundary, database/external shapes, one long return path. Stage 4 is a notation delta, not a rebuild.
- The infographic reference's differentiators are: pictorial actors, **numbered step badges sitting on wires**, labelled loops, and repeated comparison frames (Pros/Cons). A grep across `capability/` finds no badge/callout/figure/caption DSL capability (matches are incidental tokens/CSS) — these are genuine, small, general gaps.
- AGENTS.md confirms Presentation owns "measured notation and shared React rendering", Layout owns placement/routing, Export has real encoders **with a still-open file-standards gate**, and the >144/160 per-file rubric remains an unresolved gate (PROGRESS.md "Unresolved gates").

## Answers to the pressure questions

- **Missing mechanism vs authoring?** Largely authoring plus coordinated refinement. Verified existing: wires, routing/corridors, nested groups, assets, pinned measurement, export encoders. Verified missing but small and general: edge step badges, callout/annotation hierarchy distinct from plain notes, large figure nodes with captions, comparison-frame pattern. No new renderer is justified; the "no diagram-specific renderer" constraint is compatible with all of these.
- **Sequencing:** Prove-then-generalize-then-breadth is right; Stage 1's fixed scope is not (F2). The practical correction is the gap-list contract plus pull-forward, not a merged mega-stage.
- **Overfit:** Guarded by two-family reuse per stage and DSL/token-only surfaces (F3).
- **Boundaries:** Model (notation semantics), Language (DSL), Presentation (measured notation + shared React, native RF nodes), Layout (placement/corridors), Design System (tokens), Export (encoders) — one measured-geometry source (F4, F6).
- **Observations beyond tests:** F7 checklist.
- **Regression risks:** F4/F5 — file splits, complexity, import boundaries, unresolved rubric gate.

## Conclusion

The direction **can** deliver broad reusable diagram authoring: the capability substrate exists, the staging is directionally correct, and the SOP's bounded audits with continued author repairs address the real process failure. The three most important corrections, in order: **(1) F1 — Stage 1 leads with re-authoring using existing DSL; features are admitted only by demonstrated inexpressibility. (2) F2 — Stage 1's deliverable is proof + validated gap list with pull-forward, and benchmark exit is an observable checklist, not an estimate. (3) F3 — every new capability is exercised in two families before its stage closes.** With those, the plan avoids both overfitting and the repeat of postponed visual acceptance; without them, Stage 1 is where this fails.
