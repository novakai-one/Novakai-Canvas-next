## Readability and spec fidelity

The targets use short named functions, TSDoc, explicit named-function return types and domain vocabulary (admitted scene, recovery, placement, inspect, requested stamp). Intent delivery remains typed and host-owned; no React Flow JSON persistence, canonical Model mutation, fake renderer or sibling behavior import was found in these targets. Reconciliation admits before replacing committed data, retains a changed gesture, filters surviving selection, and preserves camera. The source supports those claims; this pass does not certify all Canvas invariants or the untouched host integration.

The prominent readability weakness is contract signposting: plain Transition helpers can throw, callback errors travel through a side channel, and successful diagnostics disappear at two boundaries. A reader cannot infer the complete failure path from the target return types alone. The cache's own permission-invalidation comment is stronger than its equality check.

## Required recovery, requested by the parent

Correct the three highest-consequence findings and preserve reducer diagnostics at store commit. Expose reconcile supported failures as typed Results, or the literal target score remains 5 for typed outcomes even with a protected facade. Name recovery ownership at the reviewed entry points; scattered comments do not satisfy the exact anchor.

Clearing the score gate additionally requires substantive changes to the specific deducted axes: narrow H's session role; centralize its repeated target identity; inject S's observer/browser dependencies and H's browser/hook boundaries; provide an owned step seam where the orchestrators truly need extension; and remove target-local mutable closure state if these targets must satisfy the literal immutability anchor. For T, idempotent dispatch acceptance must be a real contract if retry safety is required. Moving state or framework work out of a target only transfers the obligation: any new first-party file remains subject to its own score gate.
