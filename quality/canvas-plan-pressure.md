# Canvas plan pressure test

Reviewed the five `docs/specs/canvas/Doc*.md` documents on `feat/canvas-capability`, against Canvas requirements in baseline documents 01, 02, 03 and 05 and both requested engineering standards. Read collaborator public contracts only to verify integration feasibility. Source/specifications were not changed; no implementation or tests were created or run. Review completed within the eight-minute limit. This is a plan review, not a code-compliance score or implementation acceptance claim.

## Findings

| ID | Category | Verified finding and evidence | Smallest useful correction |
|---|---|---|---|
| C1 | major build risk | The required measured-content renderer has no available public provider. Canvas `Doc3-Modules.md:39` requires `createReactBindings({NodeContent,MeasuredContent,Marker,Button})` and says content slots reuse Presentation through public contracts. Presentation's public `ReactBindings` has only `NodeContent`, `Marker`, and `fonts` (`capability/presentation/contract/react-types.ts:15–19`); its actual public factory returns exactly those (`contract/compose.ts:26–32`), and its index exports no measured-only renderer (`contract/index.ts:40–61`). This affects Canvas edge labels and sequence labels (`Doc3:45,49`), as well as Layout's measured section titles (`capability/layout/contract/records/geometry.ts:81`). `NodeContentProps` requires a whole `VisualNode`, not `MeasuredContent` (`presentation/contract/react-types.ts:8–10`); the node vocabulary has no frameless content shape (`records/visual.ts:73–86`). The plan therefore cannot currently bind all required slots through the claimed public composition. | Explicitly name the missing public Presentation measured-content/font-scoped binding as an integration prerequisite and define the narrow required slot shape. Resolve that public contract before claiming runnable Canvas bindings. Do not reach into Presentation adapters or duplicate its primitive renderer; baseline `03-Repository.md:227,233–237,246` prohibits those shortcuts. This finding concerns Canvas's chosen dependency, not an audit of Presentation internals. |
| C2 | major build risk | The pure state contract omits information needed for two promised admission policies. `Doc2-Entities-and-Invariants.md:12` lists committed `scene` and `stamp`, but no separately requested job stamp and no persistent read-only mode. `Doc3-Modules.md:4–6` makes `transition(state,event)` pure, while `Doc3:11` requires `expect-scene` to retain the visible scene and reject results from superseded jobs; `Doc2:29` requires exact requested generation/revision/key. Reproduction at the contract level: open scene A, expect B, expect C, receive B. The listed state cannot retain A's base stamp and C's requested stamp independently. Separately, open with `readOnly:true`, then dispatch `mutation-available(true)`: no listed state field preserves the read-only prohibition required by `Doc2:35`. Hiding either fact in a mutable Canvas closure would contradict the pure API and independent-session consumers. | Add readonly `requested:SceneStamp` and persistent `readOnly:boolean` (or equivalent explicit separate records) to SessionState. Define monotonic request registration, committed stamp updates only on acceptance, and mutation eligibility as all gates together. Clarify that a host availability event cannot override read-only mode. Extend existing cases 8/9/13, without adding tests to the frozen count. |
| C3 | minor | The mandatory minimap is absent from the complete plan. Baseline `01-Functionality.md:81` explicitly includes a minimap in F28. Neither the target inventory (`Doc1:19`), component responsibilities (`Doc3:41–50`) nor the 16 acceptance oracles (`Doc5:8–23`) assigns it an owner or observable behavior. This is a reproducible feature omission, not a preference for a different navigation design. | Assign the minimap to CanvasSurface/CanvasControls using the actual React Flow binding, with explicit navigation behavior, and include it in existing binding/browser checks. No separate capability or additional suite is warranted. |

No demonstrated **engineering violation** in the planned import graph was found. No **preference** is promoted to a blocker. C1 and C2 should be resolved before calling the plan ready to build; C3 is a small completeness correction.

## Pressure checks that did not produce findings

- Coordinate rules explicitly distinguish screen camera values, section-local routes, collection-local section placement and parent-local node placement (`Doc2:9,16–17,30,33`; `Doc3:12,20`). Nested ancestor moves and parent conversion already have a dedicated oracle (`Doc5:13`). No demonstrated coordinate contradiction was found in the reviewed public contracts.
- Concurrent agent updates cancel active geometry into recovery while refreshing the committed view; submission/receipt ownership remains with the host (`Doc2:34–35`; `Doc3:27`; `Doc4:9–13`). This agrees with baseline `05-UI-UX.md:128–138`. Text drafts are correctly outside Canvas scope.
- The plan requires actual React Flow nodes/edges, stable registries, interactive-child guards and explicit camera/gesture handling (`Doc3:25–29,43–53`). Browser interaction and the release performance protocol remain mandatory Part 2 evidence (`Doc5:26`), so component tests are not misrepresented as usability proof.
- Public-entry-only imports, injected own adapters, framework-free core declarations and lazy React/CSS loading are explicit (`Doc1:25–26`; `Doc3:35–39`). No speculative restructuring or broader capability review is requested.

The five reviewed documents remain at their original aggregate **2,519 words / 186 lines**. The owner has one verified findings-only fix round; this report requests no second audit.
