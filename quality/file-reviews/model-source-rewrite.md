# Model source rewrite — author review

Baseline: `860f458`. Scope: 38 production TypeScript files (36 existing, 2 focused helpers added). Tests excluded at the user's request. This is an author review, not independent certification or runtime verification. Scores apply only to the source hashes in the companion evidence file; historical baseline scores remain unchanged.

## What changed

- All 166 named functions have TSDoc and declared return types; exported declarations have documentation.
- Named stages and intermediate results expose matching, validation and failure decisions.
- `diagnoseWhen` and `referenceIssue` both emit errors when their condition is true. Removed the opposite-polarity helpers.
- Branded object/group/section/source identities survive lookups. Layout targets discriminate their ID namespace; the persisted field names and ID grammar remain unchanged.
- Schema locals name their domain payload explicitly. Exact types describe endpoint/content/layout kind policies.
- Duplicate checking and schema-error translation moved into focused helpers. Removed unused/private helper exports.
- Preservation accepts an existing previous section; callers handle absence. Existing record match beats representation fallback, even when the matching record has no geometry.

## Static evidence and limits

- Strict TypeScript, ESLint with the unchanged Sonar ≤2 rule, formatting, dependency boundaries/cycles, and diff whitespace checks pass.
- AST inventory: 166/166 named functions have docs and explicit return types; no undocumented exported declarations found.
- Per-file Sonar maxima below measured with installed eslint-plugin-sonarjs 4.2.0 using an in-memory threshold of zero. Repository thresholds/configuration were not changed.
- Test files were neither modified nor executed. Typecheck includes their existing types. Behavioural correctness is not certified by these static results; the requested later test pass remains deferred.
- The two established exception boundaries still map thrown causes to shape diagnostics. This preserves the public outcome but loses debugging detail; reflected in KISS scores.
- No runtime extension registry or speculative injection framework was added to improve OCP scores.

## Scoring method

Authority: `docs/standards/CODING-STANDARDS.md`, all 16 file-local anchors. Integer author assessments with evidence, not lint-derived grades. No subtyping implementation is present in any target: every LSP score is **7, not demonstrated**. OCP step lists remain capped at 6; conditional dispatch requiring edits for new variants receives 0. Local traversal mutation receives Immutability 5. Passing threshold is strictly >144.

Shared evidence for undocked lenses, evaluated within each listed file:

- SRP: the responsibility in the evidence table; return assembly remains part of that responsibility.
- ISP: no infrastructure/service ports declared; data records are not service interfaces.
- DIP: imports stay within own declarations/core plus the declaration schemas' Zod dependency; no framework/storage construction. Unbranded impact identities docked explicitly.
- DRY: schemas share checked identity/record definitions; core diagnostics share constructors; known repeated writer/dispatch idioms docked explicitly.
- KISS/YAGNI: named current-domain steps, no nested ternary/conditional spread machinery or speculative runtime extensibility; remaining tracing costs docked.
- Typed errors: validation/planning failure exits are diagnostic arrays or Results; schema declarations feed checked boundaries. Generic causes remain typed `shape` outcomes.
- Recovery: mutation-free planning on the same snapshot is replayable, with Authoring named at entry boundaries; unnamed utility/schema ownership docked. This does not claim create succeeds when reapplied to an already changed snapshot.
- Demeter: direct record reads, no chained service navigation. Schema-builder chains configure the same declaration rather than navigating another service's internals.
- Immutability: readonly data, copied updates; local traversal state separately docked. Freeze explicitly requires detached data and freezes in place.
- Type safety: no any, unchecked assertions or non-null assertions; checked schema brands and narrowed unions.
- Cognitive style: no SOP-named nested/spread ternary idioms; measured branching maxima ≤2 are independent evidence, not readability proof.
- Testability: no ambient time/env/filesystem or network dependencies. This is structural testability, not a test-correctness score.
